# Tabi · UI Registry

## Архитектура интерфейса

В Tabi ровно 13 постоянных UI-модулей. Новые возможности распределяются по существующим модулям; адаптивность относится к затронутым компонентам, а не к отдельному UI-модулю.

| ID | Область | Ответственность |
|---|---|---|
| UI-01 | Шапка | Кандзи, геометрия шапки, кнопки настроек и синхронизации |
| UI-02 | Приветствие | Заголовок, отражающий состояние переезда |
| UI-03 | Показатели | Счётчики, фильтрация через показатели, компактное отображение |
| UI-04 | Навигация | Список ↔ канбан, свайп, анимации перехода, ориентация экрана |
| UI-05 | Поиск и фильтры | Поиск, фильтры и их адаптивное расположение |
| UI-06 | Прогресс | Расчёт и представление прогресса |
| UI-07 | Комнаты | Создание, сворачивание, порядок, плашки и перелистывание |
| UI-08 | Предметы | Создание, карточки, переименование, массовые действия |
| UI-09 | Канбан | Колонки по решениям, перетаскивание, компактная плотность |
| UI-10 | Настройки | Настройки интерфейса, резервное копирование, облачные секции |
| UI-11 | Название проекта | Локальное редактирование имени проекта |
| UI-12 | Требует исходной спецификации | Назначение не подтверждено; не переопределять произвольно |
| UI-13 | Темы | Komorebi, Dusk и переключение оформления |

**DS-01:** единые цвета, состояния, фокус, визуальные токены и анимационные принципы.

**CORE-01:** данные, локальное хранение, импорт/экспорт, авторизация, шифрование и синхронизация.

## Неизменяемые правила

1. Перед изменением определить модуль, ожидаемое поведение, затронутые файлы и критерии проверки.
2. Не менять соседние функции и дизайн без явной необходимости.
3. Изменения схемы данных, Supabase, RLS, ключей хранения, шифрования и синхронизации проводить отдельно и с проверкой обратной совместимости.
4. Изменения проходят через рабочую ветку, Preview, проверку и только затем `main`.
5. Проверять телефон, планшет, обе темы, свайп, перетаскивание, существующие данные и JSON-резервное копирование.
6. История экспериментов и удалений остаётся в Git, а не в этом документе.

## Открытые вопросы

- **UI-04:** устранить остаточное дёрганье при завершении свайпа без изменения логики данных.
- **UI-12:** подтвердить исходное назначение перед следующими изменениями.
