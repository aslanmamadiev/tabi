# Tabi · 旅

**Tabi** — персональное веб-приложение для организации переезда: от списка вещей и решений по каждой из них до выполнения плана.

**Приложение:** https://tabi-axm12.vercel.app/  
**Исходный код:** https://github.com/aslanmamadiev/tabi

## Как это работает

Вещи распределяются по комнатам. Каждому предмету можно назначить решение: **оставить** (красный), **не знаю** (жёлтый), **отправить / взять с собой** (зелёный) или оставить без метки. Отдельная отметка выполнения показывает, что решение уже реализовано; для неопределённых предметов завершение недоступно.

Два представления — **список по комнатам** и **канбан по решениям** — позволяют работать с одной коллекцией вещей. Между ними можно переключаться кнопками или горизонтальным свайпом. Долгое нажатие позволяет перемещать карточки.

## Возможности

- Комнаты: добавление, переименование, сворачивание и изменение порядка.
- Предметы: создание, редактирование названия прямо в карточке, удаление, поиск, фильтрация и массовые операции.
- Канбан: группировка по цветовой метке, обычная и компактная плотность.
- Прогресс: показатели завершения и оставшихся решений; компактное представление на телефонах и планшетах.
- Оформление: светлая **Komorebi**, тёмная **Dusk**, автоматическая тема и переключение по кандзи **旅**.
- Локальная работа и JSON-экспорт/импорт для резервных копий.
- Необязательная облачная синхронизация через Supabase с учётной записью и клиентским шифрованием.

Интерфейс адаптируется к телефонам, планшетам и компьютерам. Состояние предметов и решений не зависит от выбранного представления или темы.

## Начало работы

Откройте приложение. Новому пользователю доступны четыре комнаты — **Гардеробная, Гостиная, Кухня, Ванная** — с пустым списком предметов. Можно изменить комнаты, добавить вещи и постепенно назначить им решения.

Данные сохраняются локально в браузере. Для переноса между устройствами можно использовать JSON или облачную синхронизацию. Некоторые настройки интерфейса (например, название проекта, свёрнутые комнаты и плотность канбана) хранятся только локально.

## Данные и безопасность

- Облачный режим использует Supabase Auth и разграничение доступа по владельцу записи (RLS).
- Содержимое синхронизируемого JSON шифруется на клиенте с помощью PBKDF2 и AES-GCM.
- Серверная проверка версии (CAS) уменьшает риск конфликтной перезаписи, но не заменяет полноценное разрешение конфликтов.
- Перед важным импортом или заменой облачного состояния рекомендуется сохранять отдельную JSON-копию.
- Не публикуйте пароли, резервные копии с личными данными и секретные ключи. Публичный клиентский код не должен содержать серверных секретов.

## Разработка и структура

Tabi — статическое веб-приложение без обязательного этапа сборки. Основной код находится в `index.html`. Для криптографии и облачного режима требуется безопасный контекст (HTTPS или поддерживаемая локальная среда).

Функциональные изменения ведутся по идентификаторам **UI-01…UI-13**, а также **DS-01** (дизайн-система) и **CORE-01** (данные и синхронизация). Это *логические модули*, а не 13 отдельных файлов. Актуальные границы модулей и правила изменений описаны в [UI Registry](docs/UI-REGISTRY.md).

Разработка: отдельная ветка → Preview → проверка → Pull Request → `main`. Production обновляется после объединения проверенной версии.
